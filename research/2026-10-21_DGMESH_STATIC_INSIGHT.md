# DG-Mesh 静态化核读与当前算法取舍

日期：2026-10-21。用户要求仔细核读本地 `papers/DYNAMIC GAUSSIANS MESH.pdf`，判断删除 deform 是否能改善刚体重建，并给出简洁完整管线与可否证的核心 insight。仅论文/代码静态研究，不运行重建。

## 检查点 1：直接从本地 PDF 核到的机制

已通过 `pdftotext -layout` 读取本地 PDF 第 4–9、17–22 页，并核对官方项目及仓库。

- [论文，§3 / Fig.3] canonical 表示是 **Gaussians，不是固定拓扑的 canonical Mesh**。每个时刻先把 Gaussians 变形，再把它们作为带法线点云，经 DPSR 和可微 Marching Cubes 得到该时刻 Mesh。
- [论文，§3.3 / Fig.4] Mesh 反过来指导 Gaussian 分布：多个点对应同一面时合并，没有点对应的面在面心增加点，并加 anchoring 距离约束。这是在已有表面上重新分配点，不能直接等同于观测驱动的局部体素分辨率选择。
- [论文，§3.3] forward/backward deformation 和 cycle consistency 把变形空间里的点调整带回 canonical space，服务于跨时刻对应。
- [论文，§3.4] 已同时使用 Gaussian RGB、Mesh RGB、Mesh Mask、Laplacian、anchoring、cycle 损失。**不能把增加 Mask 监督或 Mesh 渲染反馈说成相对它的新贡献。**
- [论文，附录 C / 第 18 页] 作者用球变环面的例子说明重新从点提取 Mesh 可以改变拓扑；固定连接关系的模板 Mesh 变形不能做到。这支持借鉴“可重新提取表面”，不支持“deform 一定导致粘连”。
- [论文，附录 H / 第 21–22 页] 明确失败条件是极端运动或不完善分割。是否存在用户指的具体指缝粘连，需要核对图示；目前没有找到专门的指缝/假桥指标或“删除 deform 即修复粘连”的实验。
- [论文，§4.2] RTX 3090 Ti、50k 迭代，只是训练设置，不是峰值显存报告。暂无本机 12GB 结果。

## 当前先确定的判断

对静态刚体，可以令所有时刻的变形为恒等映射，并去掉时间依赖和 cycle。**这减少未知自由度，不是增加几何表达自由度。**可能的收益来自消除无用运动解释、让更多视图直接约束同一表面，以及减少部分运算；省下多少资源、质量是否提高均待测。要增加静态细节容量，还需显式增加表面点或局部场节点，删除网络不会自动做到。

更值得借鉴的是 Gaussian/表面互相反馈、Mesh 本身接受图像监督，以及每次可重新提取拓扑。对我们的窄缝问题，需要进一步让独立图像证据约束该反馈，避免把当前错误表面当作分配点的正确目标。这是机制推断，尚无实验支持或新颖性证明。

继续核查图示与实现后追加，不以本检查点替代最终判断。

来源：[官方项目](https://www.liuisabella.com/DG-Mesh/)、[官方代码](https://github.com/Isabella98Liu/DG-Mesh)、本地 PDF（ICLR 2025）。

## 检查点 2：图 5 确有用户指出的手指细节损失

已把本地 PDF 第 4、6、22 页实际渲染并查看，额外放大第 6 页 Figure 5。**用户的视觉判断有依据**：Figure 5 顶部手部红框中，左侧 GT 图可辨认多个分开的手指，右侧 DG-Mesh 的 Mesh 红框保留拇指侧分离，但其余手指呈合并块状，未恢复逐指间隙。不能仅以“论文整体优于对手”否定这个现象。

## 检查点 3：官方源码确认的两种不同容量

- [代码] `dgmesh/arguments/__init__.py` 默认 `grid_res=256`；`configs/d-nerf/jumpingjacks.yaml` 则配置 288。因此默认值不能当作所有实验实际值，代码配置 25k 迭代也不能混写成论文统一 50k。
- [代码] `scene/gaussian_model_dpsr_dynamic_anchor.py` 用 `DPSR(res=(grid_res, grid_res, grid_res))` 建场；`upsample_dpsr` 也是改变三轴整体分辨率。Gaussian 数量/分布与这一场网格分辨率是两件事。
- [推断] 增加 Gaussians 可以改善表面采样或拟合，但不会自动增加固定网格的表示自由度。窄缝若受该网格或平滑尺度限制，仅增加点数未必能开缝；这需要控制实验，不能称已证实该图的病因。
- [代码] `train.py` 除正反位置等变形外，还构造正反法线变形模型；`mesh_renderer`、法线初始化、anchoring 和导出都使用变形相关接口。静态改版不能只删除 Figure 3 中两个框或把时间都设零就宣布完成。
- [代码] 训练已有 `mask_loss`、`mesh_img_loss`、Laplacian 和 anchoring。我们把背景像素转为空域射线，在理想不透明成像下是对同一 Mask 信息的几何利用，并非增加了一种全新监督信息。

源码链接：[训练](https://github.com/Isabella98Liu/DG-Mesh/blob/main/dgmesh/train.py)、[几何模型](https://github.com/Isabella98Liu/DG-Mesh/blob/main/dgmesh/scene/gaussian_model_dpsr_dynamic_anchor.py)、[默认参数](https://github.com/Isabella98Liu/DG-Mesh/blob/main/dgmesh/arguments/__init__.py)、[示例配置](https://github.com/Isabella98Liu/DG-Mesh/blob/main/dgmesh/configs/d-nerf/jumpingjacks.yaml)。仅静态阅读，未编译/运行。

## 检查点 4：核心 insight 与唯一推荐管线

**个人判断：表面采样容量和体积场的分辨能力是两个不同瓶颈；已有 Mesh 可以指导表面点分布，却不能单独担任拓扑正确性的依据。**若假桥已经存在，按面心补点可能给假桥继续增加支持。这只是潜在反馈风险；DG-Mesh 同时有图像和 Mask 损失，不能把它描述成完全不受输入约束的自循环，更不能断言该风险已经解释 Figure 5。

我们的待验证主张保持为“观测约束驱动的局部容量分配”：用独立保留的表面/空域证据评价候选几何，先验证局部加自由度能同时改善缝与两侧表面，再接受细化。精确 Mask 空域射线与完整 Mask 重投影在理想模型下来自相同信息；潜在贡献应在定位、求解和资源分配上，而不是把同一监督换个名字。

推荐输入到输出如下（方括号表示尚待实现的核心）：

```text
多视图 RGB + 已知内外参/Mask + 物体 bbox
  → 固定 RGB/MVS 前端估计表面点和可靠法线；Mask 提供背景射线
  → 统一 object/canonical 坐标，保存 SURFACE / FREE / UNKNOWN 及来源视图
  → [全局粗标量场，提取粗 Mesh]
  → [用 Mask 重投影和表面残差自动找冲突块]
  → [同证据/同边界粗细试解，选择视图复核，按新增字节选块]
  → [共享节点/局部基函数下重拟合和重提取，允许拓扑改变]
  → 独立显式 Mesh + 观察覆盖/未知区域说明
新增照片 → 更新证据 → 重新检查受影响区域；受限批次驻留贯穿执行
```

本周沿用已有 RGB 点/Mask 接口；不把整个 DG-Mesh 安装、动态训练和静态化改写作为最小实验前置。借鉴其“Mesh 参与反馈”和“从场重新提取以允许拓扑变化”。静态 DG-Mesh 是有意义的后续对照，但删除 deform 本身不是论文贡献，也不提供局部自适应体积场。

### 若做 DG-Mesh 静态对照，具体应保留/删除什么

- 保留静态 Gaussians 及法线、Gaussian 图像监督、DPSR/可微 MC、Mesh RGB/Mask 监督，以及需单独消融的 anchoring/平滑。
- 用恒等空间映射替代正反位置、旋转、尺度、法线的时间变形；去掉 cycle 及时间依赖。appearance 固定在静态坐标，不能借每视图/每时刻外观参数掩盖几何错误。
- 统一修改法线初始化、空间归一化、anchoring、渲染、导出接口。把所有 `fid` 设零只得到一个恒定可学习映射，不等于真正删除变形网络或节省其工作区。
- 对同一个静态数据集、相同相机/Mask、相近点容量与训练预算比较动态版本和静态版本，才能讨论静态化是否改善。不能拿新静态结果与论文动态序列的数字直接比较。
- 删除 deform 不改变原本全局 `grid_res³` 的场。原实现的整体升分辨率不等同于局部稀疏细化；GPU 峰值还包括场、提取、渲染、反向图、点与优化器。没有证据给出静态版在 3060 上的峰值。

## 最难之处与最可能的否证

1. **最难的几何问题：开缝且保壁。**准确相机和 Mask 也不直接提供内壁深度。空域很强、表面稀疏时，算法可以靠削薄/删掉手指来满足背景射线。需要图像估计的两侧表面和只在评价阶段使用的 GT 同时检查；不能把恒定向内偏移当可靠实体证据。
2. **最可能被否证的学术主张：复杂容量诊断比简单残差/Mask 细化更有效。**嵌套细表示更容易拟合噪声，粗细训练最小违例之差不是缺容量的证明；选择视图若共享系统误差，也会一起支持错误。若简单策略相同预算就同样好，或诊断耗时足以让基线多细化更多块，该候选贡献不成立。先做同容量比较，再报告包含试解的成本，不能暗称同时同算力。
3. **关键工程风险：局部有效，合并失效。**自由边界补丁能开缝不代表共享场能开缝；冻结的邻域可能保留假桥，多个补丁也会互相影响。共享边界/有上下文支撑与最后整体复核必须进入最小实验，而非只拼接局部 OBJ。

### 最快暴露错误方向的实验

先冻结一个输入可见、两侧表面有支持的合成物体及图像证据，沿用小规模几何后端完成“同一粗场 → 自动选择 → 共享场 → Mesh”。三组同预算比较仍为残差优先、Mask 边界/投影混合优先、粗细试解验证优先。输出选块图、缝的空域/通路、两侧实体/表面误差、整体 Mesh 和全部诊断成本。只看训练损失下降不验收。

另一个便宜的归因检查是固定同一批表面点/法线，在不同场分辨率下提取；它能检验提取分辨率是否限制当前结果，但不证明自动分配有效。若之后有可运行的静态 DG-Mesh，再分别控制 Gaussian 容量与场网格分辨率；不要同时改变两者后把改善归因于其中一个。

下列结果都应诚实终止相应主张：

- 静态化仍粘连：说明在该例去 deform 不足以修复，不说明整条静态路线不可行。
- 固定容量重新拟合已解决：该例没有证明需要新增容量。
- 简单 Mask/残差细化已同样好：当前复杂诊断无额外价值，应简化或重新选题。
- 细化开缝但削掉薄壁：几何失败，不能报告为成功。
- 只在局部自由网格有效：共享场核心仍未验证。

**结论状态：**有可靠图示支持 DG-Mesh 未恢复部分手指间隙；没有证据把原因锁定为 deform，也未发现本论文提供“去 deform 后刚体更好”的直接消融。静态化值得作基线，推荐的资源分配核心仍需实测，创新性目前不能确认。本轮未编译、训练或测试任何重建代码。
