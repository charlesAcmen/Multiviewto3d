# 12GB 验证方案：只验证一个细结构重建核心

日期：2026-10-19。状态：**预实验协议，尚未运行**。与主报告配套，不把预算估计、成功安装、论文硬件或示意图当实测结果。

> **当前实验优先级更新：**本文为前轮位姿/采样假设的详细历史协议；资源口径、四格Oracle、实体保留指标仍适用。静态手办的唯一当前候选及新增“同容量局部细化/可表示性判据”消融，以 [第三轮方案§5–7](./2026-10-19_core_algorithm_proposal.md) 为准。用户明确要求编译/训练/测试由本人执行，本轮没有执行这些操作。

## 1. 一句话假设与研究范围

在同样的三态 Mask、带残余误差的相对位姿、SDF 后端和计算预算下，**按可信自由空间与当前几何的局部冲突安排采样/重优化**，能降低可见间隙的错误桥接，而不以删除相邻细杆或大幅损失完整度为代价。

这是假设，不是已证明贡献。保留工作题目《位姿不确定性下基于可观测自由空间的刚体细结构重建》。最终未知位姿 RGB 实验是必要项；GT/noisy pose 仅用于因果诊断。多会话先只做两段充分重叠的刚体拍摄，不承诺任意重抓取成功。

## 2. 最小实现闭环及复用边界

| 阶段 | 首版实现选择 | 验收标准 |
|---|---|---|
| 输入准备 | 合成带纹理刚体；保留原图，选30–60关键帧；保存内参、目标框和三态标签 | 不缩掉间隙；目标图像裁剪须同步改内参；没有向方法泄漏 GT 深度/几何 |
| 分割 | 第一格使用 GT 三态；第二格用可运行的 SAM 系列配置+少量人工修订 | 输出 OBJECT/FREE/UNKNOWN；报告点击/修订耗时及间隙 Mask 质量；预处理后退出进程 |
| 位姿 | 先 GT 与受控噪声；最后对象内特征的 SfM/跟踪与片段对齐 | 输入为每帧 `T_camera_from_object`；对象运动时不得使用背景相机轨迹冒充；记录失败序列 |
| 几何基线 | **NeuS2 静态哈希 SDF**，先原实现小配置 | 相同数据至少完整输出一次 Mesh 和日志；先不同时改表示、位姿和损失 |
| 候选模块 | 投影误差→可信空域；局部占据冲突→固定数量额外查询；保留全局/表面采样 | 可独立开关；额外点数、时间、显存可计量；不增加第二套完整场 |
| 导出 | 同一个场的分块查询，初始64³或128³ cells/block，加边界halo | 统一零等值面；相邻块顶点去重；检查接缝、重复面、退化三角形；不直接运行1024³整块MC |
| 观测标签 | 结合目标可见性、遮挡与多视支持标记 faces | “有投影”不等于“看到”：需深度排序/光栅化可见性；标签另存；不得把未知面删掉后只报准确率 |
| 后续纠错 | 加新视角后从 checkpoint 重优化，并有全数据从头训练参照 | 新区域改善、旧区域退化都报告；不声称精确回滚单帧 |
| 纹理 | 几何验收后分阶段烘焙 | 几何评价使用无纹理 Mesh；纹理不能掩盖粘连 |

**工程风险：**NeuS2 是 CUDA/C++ 后端，新增采样损失需要核查训练代码和反传路径；现有 Python 入口不能自动保证所有修改可做。CPU 流式图像、真正分块 MC 也不是凭改一个配置就完成。第一阶段先控制关键帧数量、用现有可容纳分辨率跑通；之后实现并验证分块导出。若核心修改超过短期能力，应首先评估改同类 PyTorch/hash 后端的成本，不能在未记录公平性前悄悄换基线。

## 3. 显存预算与测量口径

### 3.1 代码推算的硬性风险

NeuS2 已审源码 `src/marching_cubes.cu` 分配 `N³×3×sizeof(int)` 顶点索引工作区；假设另有一份 FP32 标量场：

| 整块网格边长N | 索引工作区 | 一份标量场 | 二者之和，尚不含模型/输出/临时分配 |
|---:|---:|---:|---:|
| 256 | 0.1875 GiB | 0.0625 GiB | 0.25 GiB |
| 512 | 1.5 GiB | 0.5 GiB | 2 GiB |
| 1024 | 12 GiB | 4 GiB | 16 GiB |

**这是特定代码路径的算术下界，不是训练或导出实测峰值。**单独把点查询拆成小 batch，若仍分配整块索引网格，也解决不了该问题。分块必须覆盖整个提取工作区/输出生命周期。

哈希表参数也不是总显存：当前 NeuS2 base 配置14层、每层最多2^19项、2维，理论容量上界约14.68M标量，FP32约56MiB。实际低分辨率层可更小；训练另有梯度/优化器、MLP、二阶导、射线激活、图像、占据结构及CUDA临时区。不能根据“哈希表很小”就宣布12GB可跑。

图像驻留例算：60张1280×960的RGBA图，uint8单份约281MiB，FP32单份约1.10GiB；Mask、法线、对应、多尺度副本另计。原图放CPU不等于网络查询/反传不占显存。

### 3.2 首轮资源控制（工程目标，非测量值）

- 运行前测 GPU 总量和当前空闲量。初始目标为**本任务新增占用不超过 `min(9 GiB, 启动前空闲量−1.5 GiB)`**；后台占用变化时重新评估，不把该式当硬隔离机制。
- 阶段串行：分割退出→特征/位姿退出→训练→退出/重新启动导出→纹理。保存中间结果，不常驻所有模型。
- 从小 rays/points batch 开始；候选初始每步额外点查询可设4096，设硬上限16384，再按实测调节。这是待实现的实验参数，**不是现有 NeuS2 官方命令行选项**。
- 风险区域只维护有限候选块/优先队列，不分配全局1024³不确定性、梯度或多位姿副本；位姿假设顺序投影或小批处理。
- 保留全分辨率原图；优先关键帧和patch/ray查询。若降分辨率，必须重新报告每条缝的像素宽和可观察性。
- CPU常驻缓存初始上限8GiB，实验进程RAM目标低于20GiB；大Mesh中间块落盘。两者都是首轮目标，需要实测修订。
- 可调量按顺序隔离：驻留数据→单批激活→表示容量→提取工作区；每次只改一个导致峰值的因素。不要仅凭 `empty_cache()` 报告OOM已解决。

### 3.3 每次运行必须留证

记录：代码commit/静态快照、配置、数据版本、seed、帧数、输入/裁剪分辨率、所有ray/query/block大小、参数/primitive规模、开始/结束时间、成功/失败阶段、完整错误。

适用PyTorch的阶段在同步后清零峰值，记录 `max_memory_allocated` 和 `max_memory_reserved`；另采样 `nvidia-smi` 设备/进程占用，建议100–200ms并记录间隔。短暂峰值可能被外部采样漏掉，C++/CUDA分配不在PyTorch统计中；不能声称采样最大值是精确瞬时峰值。Windows进程数据不完整时明确写N/A，保留设备占用与后台基线。

完整闭环的峰值是分阶段最大值，同时报告每阶段数字及是否串行；不能相加当并发峰值，也不能只报训练而漏掉分割/导出。OOM的运行也进入结果表，不能剔除。

## 4. 数据和实验规模

### 最小调试集

先2个程序生成对象：梳状实体、带不同宽度孔洞的板；每个有可控纹理、固体尺寸、60视角、逐像素对象/遮挡标签。用于发现坐标、SDF符号、投影、分块接缝及指标错误，不用它们做最终泛化结论。

### 最小论文验证集

- 建议至少12个几何实例，覆盖刚性手形、梳状、穿孔和细杆框架四类；按对象分开发/测试，不能同一几何换纹理后跨集合泄漏。
- 相邻间隙尺寸0.5/1/2/4/8mm是采样设计，**不代表承诺0.5mm精度**；额外记录1/2/4/8px等有效投影宽度、成像模糊与相机距离。只在预先定义的可观察集合上测“应恢复”的间隙，同时报告被排除比例。
- 光照/纹理、背景/桌面/手形遮挡、相机轨迹保持可重现。遮挡者始终不作为几何输入。
- 真实验证先4个有纹理刚体；至少一对真实窄缝、一次翻面、一次部分遮挡后补视角。没有高质量GT时只报告可复核的间隙与污染证据，不虚报毫米级全表面精度。
- GT若来自3D打印CAD，也需报告制造偏差；若来自扫描仪，报告精度/对齐误差。RGB-only尺度需要已知长度或Sim(3)对齐，不能每个局部独立对齐以消除漂移。

### 位姿与Mask因素

四格：GT pose+GT mask；GT pose+SAM mask；noisy pose+GT mask；estimated pose+SAM mask。GT三态和SAM三态都使用相同定义。

噪声至少区分小幅独立扰动、连续漂移、少量离群帧；围绕固定对象gauge施加SE(3)扰动并记录旋转/平移和投影像素误差。建议按0/0.5/1/2/4px投影残差区间汇总，比只写“1°噪声”更能对应缝宽。

不确定性估计应在开发对象校准覆盖率，不能用测试GT调安全带。保留错误匹配与对称多峰的拒绝案例；不把一个高斯协方差当所有错误的真后验。

## 5. 必须做的对照与消融

| 编号 | 设置 | 需要回答什么 |
|---|---|---|
| B0 | 原后端+同样三态Mask | 后端本身在Oracle下是否保得住缝 |
| B1 | B0+确定性FREE约束 | 改善是否仅来自增加背景射线 |
| B2 | B1+单标量帧/像素置信度 | 逐点位姿传播是否比降权有用 |
| B3 | B1+固定/噪声自适应Mask安全带 | 最重要简单基线；候选不能只是昂贵腐蚀 |
| B4 | 相同总查询量的随机/边缘/曲率/不确定性采样 | 定向冲突采样是否超出已有采样思想 |
| A1 | 可信空域判定+均匀查询 | 隔离几何判定的效果 |
| A2 | 点估计FREE+局部冲突采样 | 隔离采样调度的效果 |
| Full | 可信空域判定+局部冲突采样 | 两者是否有必要的交互收益 |
| E0 | 固定训练场，仅提高导出分辨率 | 排除仅由MC加密带来的改善 |

前期先B0/B1/B3/Full，发现信号后再展开全部；不要一开始乘出数千次训练。每个采样对照同时做等总点查询量和等墙钟时间两种比较，记录额外位姿假设投影成本；同样的点击/ROI信息给所有对照。代表性设置至少3个seed，按对象汇总区间，帧不能当独立样本扩大显著性。

外部对照仅保留必要的：**MILo base**用于同输入高质量Mesh/资源参照；**ObjectCarver**用于已知位姿下的遮挡分离参照（若12GB无法原样复现须如实记OOM，单对象改版明确命名）。**Dyn-HOR**用于后期真实自由交互参照，WIP与预处理单列。不要为论文表格强行复现全部13项；BundleSDF/UA-Pose是RGB-D不同输入，不能混入同条件排行榜。

## 6. 评价定义：避免靠删模型拿高分

- **Gap survival**：GT预定义局部ROI及入口/出口，在ROI内检查重建自由空间是否有通路；禁止绕到ROI外。报告通路最窄处宽度，不只报告二值连通。
- **False bridge volume**：闭合占据可靠时，在GT间隙ROI中计算预测实体占比；开放Mesh不要强行填洞后声称原始体积正确，改用表面侵入面积/射线违例。
- **邻近细杆保留**：每根杆的GT表面召回、厚度误差和断裂率。gap survival上升而杆召回下降不能算成功。
- **Minimum recoverable gap**：明确成功率阈值、可见性和姿态噪声，跨实例汇总；不是选一个最小成功案例。
- **Confirmed free-space violation**：在独立保留视角/GT标签下评价，不只在训练Mask上自证；同时测误刻率。
- **整体几何**：Chamfer、F-score（明确单位/阈值）、normal consistency、accuracy/completeness，分别报告观察支持区域与整体输出。
- **污染**：目标外输出表面积/支持物接触ROI中的侵入，报告Mask误差和位姿误差条件。
- **拒绝与覆盖**：保留未知/缺面比例、置信判定覆盖率；低覆盖的高精度不能与完整输出直接比较。
- **资源**：阶段显存、RAM、总时间、预处理时间、导出时间、OOM比例，以及质量—内存—时间曲线。

## 7. 纠错实验与采集可行性边界

第一段遮挡部分孔/指缝，第二段真正看到该处。比较第一段结果、新数据重优化、全数据从头训练；对新区域和旧区域分别统计。保持相同新观测和标注预算。无法对齐的第二段必须记失败，不能手动完美配准后称自动多会话成功。

对于局部直缝，宽w和投影误差安全半径r满足 `w<=2r` 时，简单保守判定没有剩余可信缝内区域。这是应当新增近景/侧视或改进位姿的情况，不是损失设计能保证解决的情况。论文应报告这种失败/拒绝边界。

## 8. 六周可行性审查与停止条件

| 时间窗口（计划） | 产物 | 继续条件 |
|---|---|---|
| 第1周 | 一个合成对象端到端Mesh、逐阶段显存、坐标/导出检查 | 12GB内完成；不能只训练不导出 |
| 第2周 | 四格Oracle的前3格、B0/B1/B3及细缝指标 | 能稳定复现并区分分割/位姿/后端故障 |
| 第3–4周 | Full与简化消融、等预算比较 | 优势跨对象成立且不是删杆/多算力/多标签 |
| 第5周 | estimated pose+SAM、真实刚体与遮挡 | 有可重复完整输入→Mesh记录；失败保留 |
| 第6周 | 新视角纠错、资源曲线、先例逐式复核 | 决定值得继续论文，还是当前假设被否定 |

可预先登记一个**暂定工程门槛**：在开发集选定工作点后，测试集误桥占据相对B3降低至少20%，细杆召回与整体F-score下降各不超过2个百分点；同时端到端不OOM。该数字不是领域公认标准或已达结果，须在正式测试前与导师确定；误桥基线接近零时改用绝对误差与置信区间，不能制造巨大相对改进。

停止/改判条件：GT第一格仍失败且无法定位；收益被自适应腐蚀完全解释；只靠更多采样；收益来自削掉实体或大量拒绝；直接先例已有同构机制；完整流程仍无法在本机运行。遇到这些条件就明确写“当前不能作为论文核心”，不要继续扩成通用扫描器来掩盖问题。

## 9. 服务器扩展的边界

上述最小闭环不假定A6000。若取得服务器授权，可用于高配置MILo/Neuralangelo质量上界、更多对象和更多seed、完整重基线复现。必须保留本机12GB结果；不能用服务器跑通来替代资源约束验收。

**最终定位：这是一个可执行、可被实验否定的课题验证方案。它尚不是已验证的12GB高精度扫描系统，也不是已确认的新颖贡献。**
